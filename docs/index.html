Overview

Ecco UI is a small companion library for Ecco CSS. The classless core stays classless. These are opt-in HTML patterns: navs, cards, heroes, and modals that reuse --ecco-* tokens and need almost no extra CSS or JS.

  • Copy-paste HTML snippets, ready for production pages
  • Styles sit on Ecco CSS variables (light/dark included)
  • HTML + CSS first; tiny JS only for tabs and modals
  • Works in plain HTML, React, Vue, Svelte, and friends

How to read these docs. Open Preview to try a component. HTML shows the markup. Hit Copy. Standalone files also live in snippets/ in the repo.

Install

Link Ecco CSS first, then Ecco UI. Add the script only if you use tabs or modals. 

<link
  rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/arpalanca/eccocss@main/dist/ecco.min.css"
/>
<link
  rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/arpalanca/ecco-ui@main/dist/ecco-ui.min.css"
/>
<!-- Optional: tabs + modals -->
<script src="https://cdn.jsdelivr.net/gh/arpalanca/ecco-ui@main/dist/ecco-ui.min.js" defer></script>

For production, pin a tag or commit SHA instead of @main. 

npm install github:arpalanca/eccocss github:arpalanca/ecco-ui
@import "eccocss/dist/ecco.min.css";
@import "ecco-ui/dist/ecco-ui.min.css";
import "ecco-ui/dist/ecco-ui.min.js";
// or: import { ... } via window.EccoUI after the script loads
  • ecco-ui.min.css
  • ecco-ui.min.js (optional)
  • Download ZIP

Usage

Paste a snippet. Keep Ecco’s semantic landmarks for page chrome. Use .ecco-full when a block should span the viewport (nav, hero, footer). 

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <meta name="color-scheme" content="light dark" />
    <title>Hello Ecco UI</title>
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/arpalanca/eccocss@main/dist/ecco.min.css" />
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/arpalanca/ecco-ui@main/dist/ecco-ui.min.css" />
  </head>
  <body>
    <!-- paste a nav / hero snippet -->
    <main>
      <article class="ecco-card">
        <h3 class="ecco-card-title">Ready</h3>
        <p class="ecco-card-body">Copy the HTML. Ship the UI.</p>
      </article>
    </main>
  </body>
</html>

With Ecco CSS

Ecco UI does not fork or replace Ecco CSS. Think of it as the “composed patterns” layer on top of the classless core.

  • Ecco CSS: style by tag: headings, forms, tables, buttons, dialogs
  • Ecco UI: opt-in classes for multi-part UI: .ecco-card, .ecco-nav, …
  • Both share --ecco-* tokens. Theme once; both follow.

Rule of thumb

If a single semantic element is enough, stay classless. Reach for Ecco UI when you need a pattern with structure.

Accordion

Zero JS. Stacked details with a light Ecco UI skin.

Do I need JavaScript?

Only for tabs and modals. Accordion uses native details.

Does this replace Ecco CSS?

No. Ecco UI is a companion. Link Ecco CSS first.

Can I theme these?

Yes. Override the same --ecco-* tokens.

<div class="ecco-accordion">
  <details open>
    <summary>Do I need JavaScript?</summary>
    <p>Only for tabs and modals.</p>
  </details>
  <details>
    <summary>Does this replace Ecco CSS?</summary>
    <p>No. It's a companion.</p>
  </details>
</div>

Frameworks

Ecco UI is HTML-first. In React, Vue, or Svelte you import the CSS once, paste the markup into your template, and initialize JS after mount when you use tabs or modals.

React

Use className. Self-close void tags. Call EccoUI.init() in useEffect if you render tabs/modals client-side. 

import "eccocss/dist/ecco.min.css";
import "ecco-ui/dist/ecco-ui.min.css";
import { useEffect } from "react";

export function AlertCard() {
  useEffect(() => {
    // optional: only needed for tabs/modals after client render
    window.EccoUI?.init();
  }, []);

  return (
    <article className="ecco-card">
      <h3 className="ecco-card-title">Ship it</h3>
      <p className="ecco-card-body">Copy the HTML. Adapt class → className.</p>
      <div className="ecco-card-footer">
        <button type="button">Continue</button>
      </div>
    </article>
  );
}

Vue

Import styles in main.js or the SFC. Templates keep class as-is. Use onMounted for EccoUI.init(). 

<script setup>
import { onMounted } from "vue";
import "eccocss/dist/ecco.min.css";
import "ecco-ui/dist/ecco-ui.min.css";
import "ecco-ui/dist/ecco-ui.min.js";

onMounted(() => {
  window.EccoUI?.init();
});
</script>

<template>
  <div class="ecco-alert ecco-alert--success" role="status">
    <span class="ecco-alert-icon" aria-hidden="true">✓</span>
    <div class="ecco-alert-body">
      <strong>Ready</strong>
      <p>Same markup as the HTML snippet.</p>
    </div>
  </div>
</template>

Svelte

Import CSS in +layout.svelte or the component. Markup matches the snippets. Initialize in onMount. 

<script>
  import { onMount } from "svelte";
  import "eccocss/dist/ecco.min.css";
  import "ecco-ui/dist/ecco-ui.min.css";
  import "ecco-ui/dist/ecco-ui.min.js";

  onMount(() => {
    window.EccoUI?.init();
  });
</script>

Framework tip

You do not need wrappers for every component. Treat snippets as the source of truth. Paste, rename attributes for JSX, and keep accessibility attributes intact.
